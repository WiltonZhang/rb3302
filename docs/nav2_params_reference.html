RB3302 Nav2 Parameters

What every parameter in the Wave Rover's Nav2 file does, and what changing it tunes. The planning_astar copy is identical. Values tagged launch are overwritten by planning.launch.py at start-up; rows tagged no effect are set but do nothing in this setup.

What runs in a graded run

PoseThe EKF (set up in the launch file, not in this yaml) publishes /odom; amcl corrects it against the map. Launched with raw_odom_topic:=/odom/raw_signed, the EKF reads its wheel speed from course_runner's odom_sign, which restores the sign the board leaves off (without it, turning on the spot and reversing read as driving forward).
Startcourse_runner publishes the start pose, then asks amcl for stationary updates (request_nomotion_update) until the scan lies on mapped walls, and clears both costmaps. The robot doesn't move.
Legs and corner arcscourse_runner sends its own grid path to controller_server, which runs RPP (FollowPath). RPP → velocity_smoother → /cmd_vel. While a leg runs, course_runner watches the global costmap 1.2 m ahead; a square that becomes blocked stops the leg and it is replanned around it.
Turn before each legbehavior_server Spin, on the square centre (also the start spin with --localise spin). It publishes straight to /cmd_vel, so the velocity smoother's limits don't apply to it.
Only if a grid leg failscourse_runner hands the leg to navigate_to_pose (bt_navigator + planner_server).
Only with --planner nav2waypoint_follower.
Never calledsmoother_server.

Every node also has use_sim_time: false: use the robot's clock, not a simulator's launch.
